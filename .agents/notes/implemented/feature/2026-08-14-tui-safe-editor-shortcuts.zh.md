# Agent Note: TUI 安全编辑器快捷键

Status: implemented

[English](2026-08-14-tui-safe-editor-shortcuts.md) | 中文

## 问题

恢复后的 TUI 把 Ctrl+D 当作无条件的空闲退出键，并让 Ctrl+C 在空提示词时立即退出；模型选择与帮助也只通过斜杠命令公开，常驻任务清单没有键盘控制，进行中的提示词无法暂时停放，Ctrl+L 与 `/clear` 也都只是重绘视图。这使普通的向前删除按键具有破坏性，也让主编辑器落后于 Claude Code 当前的[交互模式](https://code.claude.com/docs/en/interactive-mode)与[键绑定](https://code.claude.com/docs/en/keybindings)契约：存在文本时 Ctrl+D 向前删除，从空提示词退出则要求及时再次按下；`?` 只在空提示词时切换快捷键帮助；Alt+P 打开模型选择；Ctrl+T 切换任务清单；Ctrl+S 暂存非空提示词，或从空编辑器恢复它；两秒内再次按下 Ctrl+L 则通过 `/clear` 开始新对话。

## 决策

主输入监听器现在持有一个 800 ms、按键特定的空闲退出确认。编辑器为空时，首次 Ctrl+C 或 Ctrl+D 会绘制临时编辑器提示；窗口内再次按下同一个键才请求正常关闭。其他输入、超时、进入运行状态、显式退出或 TUI dispose 都会清除该状态与定时器。Ctrl+C 仍优先保留取消前台 Shell、取消活动轮次以及清除非空草稿的行为。

存在草稿文本时，全局监听器不会消费 Ctrl+D，而是让它到达 pi-tui 现有的向前删除绑定。Shell 或 agent 工作活动时，Ctrl+D 仍会变为警告，因此不能绕过存活工作而退出。`/exit` 与 `/quit` 仍是显式的单步命令。

空提示词中的 `?` 会打开居中的 `ShortcutHelpDialog`；`?`、Escape 或 Ctrl+C 可关闭，而非空提示词中的 `?` 仍是普通输入。Alt+P 调用模型控制器的公开选择器入口，因此与不带参数的 `/model` 共享 catalog 加载、浮层生命周期、推理强度控制、选择语义与故障报告。

Ctrl+T 通过从专用容器中移除或重新加入现有 `TodoComponent` 来切换任务清单。移除不会丢失组件状态，因此隐藏期间的 `todo/write` 事件仍会替换清单，再次显示时会绘制最新快照。浮层输入优先于这项主编辑器绑定；切换既不改变草稿，也不创建会话事件或模型消息。这些编辑器交互只存在于终端。

Ctrl+S 会对编辑器文本、光标、pi-tui 大段粘贴注册表及计数器和原始撤销栈取快照。清空与恢复会在 `setText()` 周围使用全新的临时撤销栈，随后恢复操作重新连接已保存的粘贴注册表和撤销栈；这样可以避免临时状态变化擦除粘贴载荷，或进入用户的撤销历史。非空时按下会保存或替换唯一暂存，空白时按下会恢复并消费暂存，没有暂存时在空白编辑器按下则不执行任何操作。浮层输入仍有更高优先级，因此历史搜索中的 Ctrl+S 保持原有的作用域行为。暂存只存在于一次 TUI 挂载的终端本地，不创建会话事件或模型消息。

Ctrl+L 总会请求一次硬重绘并保留编辑器草稿。Agent 与前台 Shell 均空闲时，首次按下还会布防一个两秒确认；无关按键、超时、状态转换或关闭都会解除确认。确认使用编辑器下方的专用临时行，因为 pi-tui 的编辑器 hint 会在存在草稿文本时有意隐藏。及时再次按下 Ctrl+L 与手动输入 `/clear` 会调用同一个新会话例程。活动工作会阻止该例程。

共用例程会 flush 当前会话、排空终端输入、快照已选 provider、model 与推理强度，并调用可选的 `TuiRuntime.swapFresh` 边界。随附的 runner 会先在同一工作目录中准备一个携带已选 provider/model、标识为 `session-<uuid>` 的 agent，再退役旧 handle，最后才提交替代并用完整选择信息发布 ready 事件。创建失败不会触碰旧 agent；退役失败会 dispose 已准备的替代项；任一种拒绝都会让旧 channel 保持可用。没有该边界的宿主会退化为仅清空视图并明确警告。旧持久会话绝不会被覆盖，且仍可恢复。

## 验证

TUI 集成测试覆盖移动光标后的 Ctrl+D 向前删除、两个确认退出键、超时后重新布防、无关按键解除确认、字面 `?` 插入、快捷键对话框的每个关闭键、Alt+P 模型选择、清单隐藏期间收到替换时的 Ctrl+T 可见性，Ctrl+S 的空操作、替换、光标、撤销栈与大段粘贴恢复且不记录动作，以及 Ctrl+L 保留草稿、超时后重新布防、无关按键解除确认、二次按下与手动 `/clear` 的 flush、选择信息延续和交换失败恢复。Runner 测试固定唯一 id、工作目录与 AgentOptions 延续、ready 事件选择信息和已准备 agent 的回滚。录制终端快照固定居中的快捷键面板、临时退出与 Ctrl+L 确认行、更新后的 `/help` 文案、隐藏后缺失的任务清单及其最新状态的恢复、空编辑器中的暂存提示，以及位于原光标处的已恢复大段粘贴标记。

一项 keyless PTY smoke 会在 Windows ConPTY 或 POSIX PTY 下启动构建后的发布 profile，打开并关闭 `?` 帮助，通过 Alt+P 选择模型与最大推理强度，执行 Ctrl+L 握手，等待替代 TUI 重新接管 bracketed-paste 输入，然后驱动真实 `todo_write` 工具。脚本适配器会拒绝任何丢失模型或推理强度的情况。该 smoke 还会验证恰好存在一份旧 `main` 日志和一份唯一的新会话日志，执行 Ctrl+T、Ctrl+S 与 Ctrl+D 流程，通过确认后的 Ctrl+D 退出，并在不发出 API 调用的情况下观察终端恢复。

## 考虑过的替代方案

**保留 Ctrl+D 全局退出并把删除分配给其他按键。** 未采用，因为这会让常见编辑操作具有破坏性，并偏离目标交互。

**把首次按键警告追加到 transcript。** 未采用，因为确认属于短暂 UI 状态；持久化会污染回放、历史和模型相邻展示。

**让 `?` 复用 `/help`，再向 transcript 追加一块内容。** 未采用，因为可切换浮层无需永久扩大会话视图即可提供可发现性。`/help` 仍保留为面向 scrollback 的持久命令参考。

**在按键处理器中复制模型选择器加载。** 未采用，因为 `/model` 已持有 catalog 解析、选择、错误处理与浮层替换。公开控制器入口可以保持单一行为。

**隐藏时丢弃任务清单，并在显示时从会话日志重建。** 未采用，因为存活的 `TodoComponent` 已消费权威 `todo/write` 事件。保留该组件而只改变其容器成员关系，无需第二条投影或回放路径即可保留最新状态。

**Ctrl+S 只保存 `editor.getText()`。** 未采用，因为 pi-tui 会把大段粘贴表示成紧凑的 `[paste #N …]` 标记，其载荷位于另一个私有注册表中；只恢复标记会把该字面标记提交给模型。

**Ctrl+S 只保存 `editor.getExpandedText()`。** 未采用，因为展开会丢失标记与载荷之间的结构，并让已保存的光标和撤销历史描述另一种文本布局。捕获狭窄且固定版本的运行时状态可以精确保留编辑器语义。

**保留 `/clear` 仅重置 transcript 视图的行为。** 未采用，因为旧对话仍会是模型的实时上下文，也不会形成可供恢复的新会话边界。

**清空后复用 `main` 会话标识。** 未采用，因为新对话会与旧持久化标识冲突，并破坏可恢复边界。

**先 dispose 旧 agent，再创建替代项。** 未采用，因为创建失败会让用户失去存活对话。先准备，并在退役失败时回滚，可以让转换拥有可恢复的提交点。

## 后果

编辑器匹配安全、上下文相关的目标行为。意外的空提示词退出需要再次按下同一个键，Ctrl+D 仍可用于编辑，Ctrl+S 可以无损停放草稿，快捷键帮助只需一个按键，模型切换不再要求键入命令，较长的任务清单也能离开 viewport 而不丢失更新，Ctrl+L 现在还能区分无害重绘与显式的新会话转换。

旧会话保持持久化且可恢复，每个清空后的对话则会在同一工作区中获得唯一标识，并从已选模型与推理强度开始。新会话转换仅限空闲工作且要求宿主具备能力；首次重绘及其两秒确认仍只存在于终端。由于 `/clear` 会重新挂载 TUI，尚未消费的挂载本地 Ctrl+S 暂存不会跨越该边界。

800 ms 退出确认与两秒 Ctrl+L 确认都有意只存在于终端本地且不可配置。Alt+P 依赖终端报告带 Alt 修饰的 P 序列；不带参数的 `/model` 仍是可移植回退。快捷键面板记录当前内置按键，但尚不是用户可重绑定的 keymap 浏览器。无损 Ctrl+S 有意依赖固定版本 pi-tui 编辑器的运行时字段；若 pi-tui 升级改变这些字段，必须同时更新适配器及其大段粘贴回归测试。

# Agent Note: TUI 直接 Shell 模式

Status: implemented

[English](2026-08-14-tui-direct-shell-mode.md) | 中文

## 问题

恢复后的 TUI 可以要求模型调用 shell 工具，但缺少类似 Claude Code 终端所预期的、由用户持有的 `! command` 路径。把该输入当作普通提示词会让执行变得间接且不确定；把它当作伪造的工具调用，则会虚构模型授权和一个从未存在的调用 id。直接路径还必须保留部署的工作目录、受管 Harness 环境、沙箱边界、取消语义、持久会话历史，以及 Windows／POSIX 执行器选择。

## 决策

提交行的首字符为 `!` 时进入直接 Shell 模式。非空命令通过组合现有的 `ctx.shell` 执行器启动一次，并携带交互会话的工作目录、中止信号、可选的 `ctx.shellEnv` 快照，以及可选的、针对该会话解析出的 `ctx.sandboxPolicy`。用户的显式提交就是授权边界，因此它不会进入模型工具审批。常驻沙箱策略仍然适用；直接模式不是不受限制的逃逸通道。TUI 使用 `ShellExecutor.start()`，因为同一条存活进程必须能在启动后移交；与前台 `run()` 不同，这个句柄没有执行器超时。

每个 TUI channel 同一时间只允许附着一条前台直接命令。其有界合并输出会增量渲染，在它结算或离开前台之前禁止再次提交。Ctrl+C 会先于普通轮次取消路径中止它；附着期间 Ctrl+D 拒绝退出；channel dispose 也会中止仍附着的命令。只输入感叹号、缺少执行器或提交第二条并发命令时，TUI 会保留可用草稿并显示终端警告。用户明确中止的前台命令和基础设施 rejection 只保留为终端通知，不会唤醒模型。

Ctrl+B 会请求可选的 `ctx.jobs` 注册表把已经存活的同一条进程接收为 `bash-N` 任务。注册表的准入、owner 与控制器检查都在移交回调之前运行；拒绝时，进程仍附着且继续由 TUI 持有。成功时会移除实时行、重新开放编辑器，并通过 `/tasks` 和模型侧 jobs 工具暴露任务。`/tasks` 是纯终端的时间点列表，展示此 agent 可见任务的 id、状态、标签和终止详情。

执行正常结算时（包括非零退出，无论仍附着还是已经后台化），TUI 都只追加一条持久的 user-role 消息，其插件来源为 `user-shell`、形式为 notice。它的 `<user-shell-command>` 外框包含原样命令、有效工作目录、有界合并输出、可用的完整流 spill 定位信息，以及退出／信号／沙箱事实。这是插件来源的上下文，而不是 human prompt 或合成工具结果。它遵循普通实时路由规则：空闲时调用 `followup()`，轮次运行时调用 `steer()`。Transcript 会把它渲染为紧凑的 `Context · user-shell` 卡片，并只剥除已知外框。

`ShellEnvRegistry.collect()` 接受公共 `ToolExecutionInput` 形状，而不再要求注册表私有的 `ToolExecution`。因此，直接用户执行无需伪造工具注册 token，也能收到与 shell 工具相同的受信任 `DSH_*` 事实。执行器仍负责在合并收集快照前清除继承的 `DSH_*` 值。

`ShellProcess.readOutput()` 是单一消费游标。因此 `UserShellProcessController` 是它唯一的读取方，并把每个 delta 分流进两个有界 `TextRetainer` 尾部：一个持久完整视图供终端渲染与最终上下文使用，另一个可重置游标供 `job_output` 使用。读取任务输出不会从完成结果中偷走字节；上游 lossy／spill 事实也会独立于两份保留尾部持续累积。

移交后的工作设置 `JobStart.completionDelivery: 'producer'`。`dsh-jobs-local` 会让该记录从 reported 状态开始，因此 TUI 已承诺交付完整 `user-shell` 上下文后，`dsh-tool-jobs` 不会再发送通用的「用 job_output 读取」完成消息。

`UserShellHistory` 会在启动前记录每条已接受命令，因此仍在运行或后来被取消的命令也会立即出现在当前 channel。光标位于 `!` 草稿末尾时，显式 Tab 会按整条命令前缀从新到旧补全。可选的 session-query 服务会惰性扩展该视图：从工作目录解析后相同（Windows 上还会规范化大小写）的最近 32 个会话中恢复已完成的 `user-shell` 消息；发现过程最多保留 100 条唯一命令，并发精确读取 4 份日志。当前会话的匹配不会等待语料发现；重复命令保留最新观察；无法读取的旧会话会被跳过；语料列表失败时可在下一次补全重试。只有已完成的结果通知会持久化，因此在结算前被取消的已接受命令仍只存在于当前进程。

包装后的自动补全提供方会把 `/` 声明为实时触发字符。pi-tui 依赖补丁允许该提供方在行首斜杠命令位置之外触发，并让后续字符、退格与删除继续处于同一路径补全状态。Pi 原生路径提供方负责引号、`~/`、绝对／相对查找、目录下钻和补全文本替换；TUI 以会话工作目录为基准。Windows 与 POSIX 都使用正斜杠作为输入／显示语法。消息行首的斜杠命令仍保持原有命令菜单优先级。

## 验证

纯契约测试固定了感叹号解析、持久消息来源、有界流／截断渲染、状态渲染和单读取方分流。TUI controller 测试固定了 cwd、受管环境、沙箱传递、实时输出、followup 交付、非零完成、草稿恢复、Ctrl+C 取消、Ctrl+D 拒绝、成功的 Ctrl+B 移交、`/tasks`、任务读取，以及真实本地注册表与 `dsh-tool-jobs` 组合下的恰好一次完成。注册表测试固定了生产方持有的完成在结算前后均为 reported。Shell-env 测试证明，不带私有 token 的公共执行输入仍会收到受管环境。

一项 keyless 录制会话快照会运行真实平台执行器，并对九种终端状态做 diff：实时输出、Ctrl+B 移交、运行中的 `/tasks`、由生产方交付的完成、项目历史 Tab 补全、实时 Shell 路径菜单、已接受路径、Ctrl+R 提示词历史搜索，以及已接受的历史结果。它还会证明三项 jobs 工具均已组合、任务已经终止且为 reported、持久上下文保留早期与晚期输出、日志中没有通用 jobs 通知，并且单纯自动补全不会新增会话事件。另一项独立的 keyless PTY 测试会启动构建产物中的 `dsh tui` Loader profile，在真实终端中观察早期输出、后台化进程、趁运行时列出它、展开完成上下文以暴露晚期输出、观察模型确认、实时补全一条预置的正斜杠路径、通过 Ctrl+R 召回精确感叹号命令，并验证 Windows ConPTY 或 POSIX PTY 的终端释放。快照 harness 会选择平台原生执行器，并规范化经过 JSON 转义的 Windows 工作目录路径。

## 考虑过的替代方案

**把感叹号行作为普通 user 文本发给模型。** 未采用，因为模型可能拒绝、改写或重复执行用户明确请求的命令，终端也无法提供确定的直接 Shell 交互。

**伪造模型工具调用和工具结果。** 未采用，因为模型没有发出该调用，也不存在合法的工具调用关联 id；这还会向审批 hook 和持久历史错误表述授权路径。

**绕过 Harness shell seam，直接使用 `child_process`。** 未采用，因为这会让平台选择、子进程清理、输出上限、受管 `DSH_*` 身份和沙箱行为脱离已交付 shell 工具使用的同一套契约。

**按下 Ctrl+B 时另起一条进程。** 未采用，因为这会重复副作用并丢失已经产生的输出。后台化只会在注册表接受后移交完全相同的存活句柄。

**让通用 jobs 报告方持有所有已移交任务的完成。** 未采用，因为它刻意通用的通知需要后续再调用 `job_output`，无法保留直接 Shell「模型自动响应完整结果」的承诺。由生产方持有交付会显式表达更丰富的上下文，并且只抑制重复报告方。

## 后果

TUI 用户现在可以用 `!` 运行一条显式的平台原生命令、观察有界输出实时到达、用 Ctrl+B 把它移入共享任务、继续提交提示词、用 `/tasks` 检查生命周期、用 Tab 召回项目命令、用正斜杠实时补全宿主路径，并围绕持久结果自动继续对话。即使 `job_output` 已消费自己的游标，模型仍只会在诚实的插件来源下看到一次完整命令输出；会话回放会保留它；前台取消也不会意外提交部分输出。未提供 `ctx.shell` 的部署会保留可用的编辑器草稿；没有 jobs 控制器的部署则会保留前台进程，并收到明确的 Ctrl+B 警告。

TUI 新增了 output-retention 运行时 peer，以及对 shell、shell-env、sandbox-policy、jobs 和 session-query seam 的可选类型级 peer。Shell-env 的公共收集契约从私有注册执行扩展为公共执行输入；jobs Service Definition 则新增协作式存活资源移交与显式完成交付所有权。每条命令的输出保留量受配置限制，被省略字节仍可通过执行器 spill 文件恢复；历史发现还分别受到条目数、会话数与并发数上限约束。未产生持久结果的命令无法跨进程召回，这是剩余的直接 Shell 历史边界。

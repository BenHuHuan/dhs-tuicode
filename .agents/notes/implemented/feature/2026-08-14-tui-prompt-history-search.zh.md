# Agent Note: TUI 提示词历史搜索

Status: implemented

[English](2026-08-14-tui-prompt-history-search.md) | 中文

## 问题

恢复后的 TUI 只在 pi 编辑器内存中保留精确提交文本，恢复会话时则从模型可见 human 消息重建该内存。因此，斜杠命令、手动 skill 命令、直接 Shell 提交和所有旧会话都会丢失。它还把 Ctrl+R 分配给 reasoning 可见性，而 Claude Code 兼容交互目标使用 Ctrl+R 反向搜索历史。Skill 正文或会话引用一旦展开，仅从现有模型与命令事件无法还原精确输入；无界预读又会让终端启动依赖每一份已存日志。

## 决策

Ctrl+R 会打开全 viewport 的提示词历史对话框，且不修改当前编辑器草稿。初始作用域为当前会话；Ctrl+S 依次切换到当前项目、所有项目，再回到当前会话。大小写不敏感的字面过滤、从新到旧排序、按最新观察折叠重复项、Up/Down 与 Page Up/Page Down 导航、Tab 插入、Enter 插入并立即提交，以及 Esc／Ctrl+C／空查询 Backspace 取消，都由终端持有。Reasoning 可见性仍通过 `/details` 选择器和 `/details reasoning [on|off]` 提供。

每次通过其提交形式专属准入检查的非空编辑器提交，都会在命令执行、Shell 启动、skill 加载或模型交付前，把精确的 trim 后文本追加为只写日志的 `tui/input` 事件。连续的完全相同输入不会再追加事件。该事件从不进入 `deriveMessages()` 或模型上下文；包级 invariant 会拒绝空文本和相邻重复。普通提示词、斜杠命令、`/skill:` 调用、直接 Shell 命令与异步准备的会话引用提示词因此共享一份诚实的召回来源，无需私有旁路文件。

当前会话会同步建立索引。第一个 `tui/input` 事件出现后，精确事件从该点起成为权威来源，因此后续 `user/message` 与 `command/run` 记录不会重复同一提交。在该边界之前，旧会话会恢复直接 user 消息、用户来源的斜杠命令与已完成的 `user-shell` 结果。已展开的旧版 `<skill>` 正文会被省略，因为无法精确重建原始 `/skill:` 命令。

项目与所有项目作用域会惰性借用可选的 `ctx.sessionQuery` 服务。单次扫描最多检查 `historyMaxSessions` 个旧会话、并发读取 `historyScanConcurrency` 份精确日志，并返回最多 `historyMaxEntries` 条唯一匹配。候选预算的一半保留给近期同项目会话，其余按全局新近度填充，因此会话很多的单一工作区无法饿死所有项目召回。列表失败可以重试；单个不可读旧会话会被跳过；dispose 会中止可取消的列表工作，并忽略已经在途的精确读取。`maxHistoryOptions` 另行限制可见行数。

## 验证

提示词历史单元测试固定了精确／旧版索引、相邻与结果级去重、旧版 skill 省略、规范化项目作用域、平衡的有界发现、渐进结果、并发、不可读会话隔离、重试、dispose 和非法边界。对话框测试固定了过滤、作用域切换、导航、插入、提交、取消、粘贴处理、分页及加载／失败状态。TUI 集成测试覆盖每一种已接受输入形式、草稿保留、Tab 与 Enter 差异，以及项目／所有项目持久化。包级 invariant 覆盖畸形和相邻重复的 `tui/input` 事件。

Keyless 录制终端快照会在真实平台 Shell 命令之后渲染 Ctrl+R 搜索与已接受的编辑器结果。根 snapshot lane 现在同时收集包持有的 TUI 终端快照与组装 app 快照，因此 renderer golden 不会再静默落在 CI 之外。构建产物中的 `dsh` PTY smoke 会通过 Windows ConPTY 或 POSIX PTY 执行同一搜索与 Tab 插入，在不使用 API key 的情况下验证持久事件，并观察终端恢复。

## 考虑过的替代方案

**持久化一份私有 readline 风格历史文件。** 未采用，因为这会在会话日志之外再建立一套耐久性、锁、工作区身份和保留系统，却仍无法可信关联到已被 TUI 接受的动作。

**完全从现有模型可见事件与命令事件派生历史。** 未采用，因为已展开 skill、已准备引用、已取消 Shell 命令及其他经过转换的输入无法反推回精确编辑器文本。把近似值显示成可执行历史并不诚实。

**TUI 挂载时预读所有会话。** 未采用，因为终端启动成本会随整个存储增长，一个损坏邻居也可能拖延无关的当前会话交互。发现过程保持惰性、有界、渐进、可取消且隔离失败。

**保留 Ctrl+R reasoning 切换。** 未采用，因为它与目标反向历史交互冲突，而 reasoning 已有显式 `/details` 接口。用户仍可切换 reasoning，无需占用惯用的历史快捷键。

## 后果

精确的已接受 TUI 输入现在可以跨恢复保留，并在有界项目或全局历史中召回，且不会进入模型上下文。Tab 是安全的仅编辑接受方式；Enter 保留所选形式的普通执行路径；取消不会改动草稿。Session-query 缺失或某份旧日志不可读时，跨会话结果仍是建议性的，而当前会话召回仍保持同步。

持久化词汇新增 `tui/input`，因此每条非连续重复的已接受提交都会新增一个只写日志事件并增加事件诊断计数，但不增加 token。现有会话保持 best-effort 兼容；事件出现前的手动 skill 调用会有意缺席，而不会被生成后的指令正文替代。扫描上限以超大存储中的穷尽召回换取可预测的终端延迟和有界 I/O。

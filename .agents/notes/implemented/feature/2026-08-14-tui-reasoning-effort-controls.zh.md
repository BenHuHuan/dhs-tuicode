# Agent Note：TUI 中由适配器主导的推理强度控制

Status: implemented

[English](2026-08-14-tui-reasoning-effort-controls.md) | 中文

## 问题

Claude Code 在[交互模式参考](https://code.claude.com/docs/en/interactive-mode)中用 Alt+T 切换扩展思考，并在[命令参考](https://code.claude.com/docs/en/commands)中用 `/effort [level|auto]` 直接或交互控制推理强度。恢复后的 DeepSeek Harness TUI 只能在 `/model` 中通过 Shift+Tab 选择推理强度，因此改变当前路由的强度必须重新打开模型目录，也没有易发现的 thinking 切换键。

DeepSeek Harness 适配器持有每个精确模型的推理元数据：支持的强度按显示顺序排列，可选默认值会具体化适配器配置，而缺少默认值会保留提供方行为。若 TUI 假定固定强度名称，或把每个推理模型都视为可切换，就会提供无效值、错误描述始终思考的模型，或为适配器未公布推理能力的模型虚构支持。

## 决策

TUI 在 `/model` 旁注册 `/effort [level|auto]`。不带参数的 `/effort` 会打开仅面向当前精确提供方／模型路由的选择器。首项为 `Auto`，它省略 `reasoningEffort` 并保留适配器或提供方默认行为；其余各项按适配器偏好的顺序取自公布列表。Up/Down 与 Left/Right 会在同一列表中循环移动。带名称的参数接受已公布 id 或无歧义的显示名称，不受支持的值则报告精确可用 id。

只有当前模型同时公布 `off` 和至少一个非 `off` 强度时，Alt+T 才执行切换。切换到关闭时会记住当前已公布的非 `off` 强度，包括已公布的非 `off` 默认值。切换到开启时，会先恢复该精确路由最近使用且仍有效的非 `off` 强度，再依次回退到已公布的非 `off` 默认值和首个已公布非 `off` 项。没有推理元数据、没有 `off` 或没有非 `off` 项的模型分别收到不同的终端警告；TUI 绝不合成缺失能力。

模型目录操作共用一个串行控制器队列，因此 `/model`、`/effort` 与 Alt+T 不会在异步目录读取后以不同于输入的顺序提交。模型和强度对话框会互相关闭；若对话框打开期间路由已变化，强度对话框会拒绝覆盖它。特定路由的切换记忆属于一个已挂载聊天 channel，并会在复用前根据当前元数据重新验证。

强度变更会替换 channel 共享的 `ModelSelectionRef.current`，但不提交编辑器文本，也不追加会话事件。它们保留草稿，并在轮次运行时仍可使用。提示词组装会为一个步骤建立选择快照，因此进行中的步骤保持一致，变更后的强度用于后续步骤。只有选择真正到达模型时，请求 header 才会记录它；未使用的 UI 选择只存在于进程本地。

## 验证

挂载级 TUI 测试固定了草稿保留、特定路由的关闭／开启恢复、`auto` 清除继承的请求强度、轮次运行中变更、直接参数、选择器导航，以及无推理、无 `off` 和仅 `off` 三种失败状态。确定性终端快照固定了路由标签、Auto 语义、适配器顺序、描述和键盘提示。

构建产物的无密钥 PTY 对话会选择脚本推理模型，发送原始 Alt+T 输入并观察 `Off`，再通过 `/effort` 恢复 `Max`，随后继续经过完整组合配置的后台 agent（智能体）控制、上下文诊断、状态卡和终端干净释放。类型、lint、文档、包构建、单元、快照与完整组合 e2e 检查覆盖发布路径。

## 考虑过的替代方案

**硬编码与 Claude 兼容的强度名称。** 未采用，因为适配器元数据才是每条精确路由的权威。提供方可能增加档位、省略 `off`、只公开 `off`，或使用另一组有序值。

**把缺少显式强度视为已启用 thinking。** 未采用，因为 `auto` 可能表示适配器默认值，也可能表示不透明的提供方默认值，其中包括禁用默认值。存在 `off` 时，Alt+T 可以把该状态切换为关闭，但无法诚实地把未知默认行为标为某个固定的已启用档位。

**立即持久化每次 UI 选择。** 未采用，因为选择是请求路由状态，不是对话内容。持久请求 header 已记录真正到达模型的值，而持久化未使用的点击会产生没有模型效果的会话事实。

**复用 `/details reasoning`。** 未采用，因为该命令控制 transcript（文本记录）中是否渲染已记录的推理块。请求强度与 transcript 可见性是相互独立的设置，改变一项绝不能暗中改变另一项。

## 后果

终端用户无需重新打开模型选择器即可控制当前路由的推理强度，同时适配器仍完全主导有效选择和默认值。同一套 UI 可用于强度集合不同的提供方，并会解释不支持的切换状态，而不是发送适配器将拒绝的请求。

每次操作都会读取建议性模型目录，因此可能报告目录故障。切换记忆有意只持续到当前 TUI 挂载结束，适配器元数据变化也可能使其失效。只改变强度仍停留在同一提供方／模型路由，但提供方是否按推理设置划分缓存由适配器决定，因此 TUI 不假定不同强度值间可复用缓存。
